## 1. 進め方

- 下のフェーズの順に進める。各フェーズの終わりに、動作確認とテストが通る状態にする
- 1コミット = 1つのまとまった変更。コミットメッセージは日本語で「何をしたか」を1行で書く(v1 と同じ)
- 機能を作るときは、**画面(共通コンポーネントを使う)・処理・テストを同じコミットに含める**
- UI/UX が今回の柱なので、**共通コンポーネント(フェーズ2)を先に作り、各画面はそれを組み合わせて作る**。画面ごとに独自のスタイルを書かない

## 3. テストの方針

### 3.1 Unit テスト(`tests/Unit`)

DB や API に依存しない、純粋なロジックを対象にする。

| 対象 | 確認すること |
|---|---|
| `GradeResultParser` | 正常な結果、件数の不一致、position の重複・抜け、空文字、点数の範囲外 |
| プロンプトの組み立て | タグで囲まれること、`<` `>` のエスケープ、採点レベルごとの文言 |
| `CostCalculator` | 計算結果、単価が未設定のモデル |
| Enum | ラベル、採点方針の文言 |

### 3.2 Feature テスト(`tests/Feature`)

| 対象 | 確認すること |
|---|---|
| 認証 | ログイン / ログアウト、未ログインでのアクセス拒否、試行回数の制限 |
| カテゴリ / セクション / 問題 | 作成・更新・削除、バリデーション、cascade 削除、10問の上限 |
| 回答の送信 | Attempt と Answer の保存、Job の投入、リダイレクト、他セクションの問題の混入を拒否、weak モードの対象チェック |
| `GradeAttempt` Job | 成功時に scores と使用量が保存されること、失敗時に failed になること、完了済みの挑戦は処理しないこと |
| 結果画面 | 状態ごとの表示、状態確認 API、再採点 |
| 集計 | 最新の点数、前回の点数、苦手問題の抽出(未採点・失敗の挑戦を除くこと) |
| 履歴の整理 | 11件目以降の削除、空になった挑戦の削除 |
| 権限 | 他人の問題・挑戦に 404 が返ること |

- Claude API は、テストでは `FakeGradingService` に差し替える
- `ClaudeGradingService` の2段階の呼び出しは、API クライアントをモックして確認する
